# HaoBlog 本地启动指南

本文适用于本地开发和阶段五本地综合验收。默认使用 Docker Compose 提供 PostgreSQL/pgvector、Spring Boot API 和 Nuxt Web；生产 Compose 只用于与 CI 等价的独立本地验收或真实生产环境，不作为日常开发启动方式。

## 最简启动

仅用于本机快速验证，不要用于生产环境。需要 Docker Desktop 已启动。

Windows PowerShell：

```powershell
Copy-Item infra/compose/.env.ci.example .env.local
docker compose --env-file .env.local -f infra/compose/compose.dev.yml up -d --build
```

POSIX Shell：

```sh
cp infra/compose/.env.ci.example .env.local
docker compose --env-file .env.local -f infra/compose/compose.dev.yml up -d --build
```

然后访问 <http://localhost:3000>。本地测试登录账号为 `admin`，密码为 `password`。

停止服务但保留数据库：

```powershell
docker compose --env-file .env.local -f infra/compose/compose.dev.yml down
```

如果要删除本地数据库数据，在确认数据不再需要后执行 `down -v`。

## 2. 首次准备

所有命令都从仓库根目录 `G:/work/HaoBlog`（或当前检出的仓库目录）执行。

### 2.1 创建本地环境文件

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

POSIX Shell：

```sh
cp .env.example .env
```

编辑 `.env`，至少替换以下值：

```dotenv
POSTGRES_PASSWORD=仅用于本机的随机密码
JDBC_DATABASE_PASSWORD=与 POSTGRES_PASSWORD 相同
HAOBLOG_ADMIN_USERNAME=admin
HAOBLOG_ADMIN_PASSWORD_HASH=BCrypt 哈希
```

`HAOBLOG_ADMIN_PASSWORD_HASH` 必须是 BCrypt 哈希，不能写明文密码。仓库中的 `infra/compose/.env.ci.example` 提供了测试用哈希，对应测试密码为 `password`，只适合临时本地验证；个人开发建议生成自己的哈希并只保存在未提交的 `.env` 中。

不要把 `.env` 提交到 Git，也不要把真实密码、OSS AccessKey 或生产连接信息写入 `.env.example`。

评论通知默认关闭。需要本地联调时，只在未提交的 `.env` 中设置 `HAOBLOG_COMMENT_NOTIFICATION_ENABLED=true`，并提供 SMTP 主机、端口、用户名、密码、TLS、站长接收地址和发件地址；仓库示例只使用占位值。API 会使用 5 秒连接、3 秒读取、5 秒写入超时。通知发送失败只进入 Outbox 重试，不会回滚评论提交或审核。

阶段五新增音乐清单配置 `HAOBLOG_MUSIC_MANIFEST_URL`：生产必须是绝对 HTTPS 地址；local/dev 可使用 localhost HTTP。清单未配置时音乐默认关闭，Studio 开启音乐会返回 `MUSIC_MANIFEST_NOT_CONFIGURED`。其余服务端环境变量分为数据库 `JDBC_DATABASE_*`、管理员 `HAOBLOG_ADMIN_*`、公共地址 `HAOBLOG_PUBLIC_BASE_URL`、评论安全 `HAOBLOG_COMMENT_SECURITY_KEY`、评论通知 `HAOBLOG_COMMENT_NOTIFICATION_*`、OSS `HAOBLOG_OSS_*` 和生产 Compose 的 `HAOBLOG_DOMAIN`/`HAOBLOG_API_IMAGE`/`HAOBLOG_WEB_IMAGE`。`HAOBLOG_COMMENT_SECURITY_KEY` 必须是稳定的高熵服务端密钥；SMTP 密码、OSS 密钥、音乐清单和生产域名只放在未提交的外部环境文件中。

## 3. 推荐方式：Compose 启动完整开发栈

### 3.1 启动

Windows PowerShell：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

POSIX Shell：

```sh
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

首次启动会构建 API 和 Web 镜像，可能需要较长时间。开发 Compose 包含：

- PostgreSQL 17 + pgvector，宿主机默认 `127.0.0.1:5432`。
- Spring Boot API，宿主机默认 `127.0.0.1:8080`。
- Nuxt Web，宿主机默认 `127.0.0.1:3000`。
- Flyway 自动从空数据库执行迁移。
- `HAOBLOG_SEED_ENABLED=true` 时写入开发种子数据。

如果端口冲突，可以在 `.env` 中调整 `POSTGRES_PORT`、`API_PORT` 或 `WEB_PORT`，然后重新执行 Compose 命令。

### 3.2 检查服务状态

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml ps
```

三个服务均应处于 `running`，并且健康检查通过。随后打开：

- Web：<http://localhost:3000>
- API 健康检查：<http://localhost:8080/actuator/health>
- 公共站点接口：<http://localhost:8080/api/v1/public/site>

健康检查只暴露状态，不会返回数据库详细信息。

### 3.3 验证完整开发栈

Windows PowerShell：

```powershell
$env:HAOBLOG_BASE_URL = 'http://localhost:3000'
corepack pnpm smoke
```

POSIX Shell：

```sh
HAOBLOG_BASE_URL=http://localhost:3000 corepack pnpm smoke
```

Smoke test 会检查首页、公共站点接口、文章详情（如果有种子文章），并确认 Actuator 没有通过 Web 公网暴露。

这种方式适合只调试某一端；PostgreSQL 仍建议由 Compose 提供。

### 4.1 只启动 PostgreSQL

```powershell

```

```sh
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d postgres
```

API 直接运行时需要在当前终端提供数据库和管理员配置。PowerShell 示例：

```powershell

$env:HAOBLOG_ADMIN_PASSWORD_HASH = '替换为 BCrypt 哈希'
$env:HAOBLOG_SEED_ENABLED = 'true'
```

POSIX Shell 示例：

```sh
export SPRING_PROFILES_ACTIVE=local
export JDBC_DATABASE_URL=jdbc:postgresql://localhost:5432/haoblog_dev
export JDBC_DATABASE_USERNAME=haoblog_dev
export JDBC_DATABASE_PASSWORD='替换为 .env 中的数据库密码'
export HAOBLOG_ADMIN_USERNAME=admin
export HAOBLOG_ADMIN_PASSWORD_HASH='替换为 BCrypt 哈希'
export HAOBLOG_SEED_ENABLED=true
```

### 4.2 启动 API

Windows PowerShell：

```powershell
Push-Location apps/api
.\mvnw.cmd spring-boot:run
Pop-Location
```

POSIX Shell：

```sh
cd apps/api
./mvnw spring-boot:run
```

API 默认监听 `http://localhost:8080`。此终端保持运行，再打开新的终端启动 Web。

### 4.3 启动 Web 开发服务器

本机直接运行时要把 Nuxt API 地址设为 `localhost`；`http://api:8080` 只适用于 Compose 网络。

Windows PowerShell：

```powershell
$env:NUXT_API_BASE_URL = 'http://localhost:8080'
corepack pnpm --dir apps/web dev
```

POSIX Shell：

```sh
export NUXT_API_BASE_URL=http://localhost:8080
corepack pnpm --dir apps/web dev
```

Web 默认监听 `http://localhost:3000`。Nuxt 服务端通过配置的 API 地址访问后端；在 Compose 网络内使用 `http://api:8080`，本机直接运行时使用 `http://localhost:8080`。

### 阶段六运行边界

生产 Compose 保留 Caddy/Web/API/PostgreSQL 内存 64/320/640/480 MiB、CPU 0.20/0.60/1.25/0.80、PID 64/128/256/128。`memswap_limit` 等于 `mem_limit`，因此容器不可使用 Swap；宿主机原有最多 2 GiB Swap 仅作系统安全垫，不作为容器 RAM。较大开发机上的容器检查只能算预验收。

- API/Web 根目录只读，唯一临时写入目录 `/tmp` 为 32/16 MiB tmpfs，启用 noexec/nosuid/nodev；临时写入占用原内存预算，重启即清空。JVM Xms/Xmx/Direct 保持 128/384/64 MiB，Node old-space 保持 192 MiB。
- API/Web 使用镜像的 haoblog/node 用户。PostgreSQL 保留官方入口以 root 初始化目录后降权为 postgres；数据卷及 `/run/postgresql` 套接字目录可写。Caddy 2.10.0 仍以 root 运行，证书/配置只写 `/data`、`/config` 命名卷；这是明确的镜像权限例外，不能称为四容器全部非 root。两者不强加任意 UID 或只读根目录。
- 四容器均设置 no-new-privileges、json-file `10m × 3`。Caddy/Web 停止宽限 30 秒，API/PostgreSQL 60 秒；API graceful shutdown 每阶段最多 20 秒，Nitro 运行时退出期限 20 秒。Java 正常 SIGTERM 退出可为 143，需同时核对优雅停机日志、OOM=false 和未发生 SIGKILL。
- Hikari 保持最大 6/最小 1，获取连接最多 2 秒、验证 1 秒。仅业务连接设置 statement_timeout=3s、lock_timeout=1s，JDBC connect/socket/cancel 超时为 2/5/1 秒。Flyway 使用同数据库地址的独立连接，不继承业务短超时；直接 `pg_dump`/维护连接也不受此设置影响。
- 邮件在短只读事务内准备最小摘要，SMTP 发送和 OSS HEAD 均在事务外；媒体完成重新加锁复核全部元数据及有效期。通知每轮只认领 1 条、完成后间隔 1 秒，租约 60 秒，最多 5 次尝试，重试间隔 10/20/40/80 秒。旧认领结果不能覆盖新认领。
- SMTP 保留连接/读/写 5/3/5 秒，另外从套接字创建起 15 秒关闭真实连接，覆盖慢速逐字节响应和 STARTTLS 底层连接；系统 DNS 解析自身仍受操作系统解析器约束。`smtp-deadline` 仅关闭套接字，不执行后台业务；业务调度池仍为 1，未启用虚拟线程。Spring Session 继续使用其内置清理机制。
- 通知是至少一次：SMTP 接受后、Outbox 标记成功前宕机仍可能重复发送；关闭通知时仍按既有行为消费事件。失败任务和未消费文章事件继续保留。当前没有审计表；已处理 Outbox、过期预览令牌与上传意图尚无明确历史保留期，不默认删除，也不清理历史版本或 OSS 对象。
- MVC 内数据库超时返回 `503 DATABASE_BUSY`、`Retry-After: 2`、`Cache-Control: no-store`，不返回 SQL/异常细节。写入重试前先确认已保存状态；过滤器/Session 与跨入口错误统一仍需后续阶段收口。

语法检查与运行态检查分开。专用项目启动后可运行（环境文件必须为该项目专用；不保存完整 inspect 环境）：

```powershell
docker compose -p <test-project> --env-file <test-env> -f infra/compose/compose.prod.yml -f <test-override> config --format json | node scripts/verify-compose-resources.mjs - <test-project>
```

脚本读取白名单 inspect 字段及 cgroup v2、PID 1 用户/no-new-privileges、挂载/端口/日志/堆参数和健康状态，拒绝越过项目边界的命名卷；不支持相应运行字段时会失败而不是填零。真正 prod 验证应使用独立测试凭据和任务级受信任 TLS CA，保留 Secure Cookie。结束用专用项目 `stop` 或 `down`，默认保留数据库卷。

### 阶段五历史验收命令

阶段五完整记录保存在本机私有的 `docs/target`，不纳入公开仓库。只使用独立项目名 `haoblog-s5-acceptance`、`infra/compose/.env.ci.example` 和专用镜像；这些占位配置不能指向真实生产数据。

```powershell
docker build -f apps/api/Dockerfile -t haoblog-api:s5-acceptance .
docker build -f apps/web/Dockerfile -t haoblog-web:s5-acceptance .

$env:HAOBLOG_API_IMAGE = 'haoblog-api:s5-acceptance'
$env:HAOBLOG_WEB_IMAGE = 'haoblog-web:s5-acceptance'
$env:HAOBLOG_PUBLIC_BASE_URL = 'http://localhost'
$env:HAOBLOG_MUSIC_MANIFEST_URL = 'https://example.invalid/manifest.json'
docker compose -p haoblog-s5-acceptance --env-file infra/compose/.env.ci.example -f infra/compose/compose.prod.yml up -d --wait --wait-timeout 180

$env:HAOBLOG_BASE_URL = 'http://localhost'
corepack pnpm smoke
$env:CI = 'true'
$env:HAOBLOG_MUSIC_TEST = 'true'
corepack pnpm --dir apps/web e2e
corepack pnpm web:budget
```

Lighthouse 对 `/`、`/garden`、`/tools` 和 `/articles/s3-08-advanced-markdown` 逐条串行执行，不共享仍工作的 Chrome。默认每个路由 3 次；本轮在 Windows 上为规避 Chrome 151 `chrome-launcher` 清理 EPERM，使用 `LHCI_NUMBER_OF_RUNS=1`，为每个路由显式启动独立 Playwright Chromium 远程调试实例并设置 `LHCI_CHROME_PORT`。普通环境可直接使用：

```powershell
$lhTemp = Join-Path (Get-Location) '.tmp-lighthouse-s5-acceptance'
New-Item -ItemType Directory -Force -Path $lhTemp | Out-Null
$env:TEMP = $lhTemp
$env:TMP = $lhTemp
$env:LHCI_EXISTING_SERVER = 'true'
$env:LHCI_BASE_URL = 'http://localhost'

foreach ($route in @('/', '/garden', '/tools', '/articles/s3-08-advanced-markdown')) {
  $env:LHCI_ARTICLE_PATH = $route
  corepack pnpm web:lighthouse
  if ($LASTEXITCODE -ne 0) { throw "Lighthouse failed: $route" }
}
```

404 必须保留真实 404 和 `noindex,nofollow`。Lighthouse 12.6.1 即使设置 `LHCI_NOINDEX=true`（内部启用 `ignore-status-code` 并取消 SEO 门槛）仍可能因非 2xx 导航返回 `NO_FCP`；不得把 Paint API 或 Playwright 结果伪装成 Lighthouse 分数。

阶段五本地结果：API 83/83 + 55/55，Web Vitest 98/98，最终 Chromium 26/26；文章初始客户端静态闭包 67,168 bytes gzip，Three 主动态 chunk 183,243 bytes gzip；首页、花园、工具 Lighthouse 三类均 1.00，固定文章为 0.91/1.00/1.00。短时资源快照和日志扫描记录在本机私有验收资料中；这些结果不等于阶段六 30 分钟 2GB 压测。

验收结束后只清理专用项目：

```powershell
$env:HAOBLOG_API_IMAGE = 'haoblog-api:s5-acceptance'
$env:HAOBLOG_WEB_IMAGE = 'haoblog-web:s5-acceptance'
docker compose -p haoblog-s5-acceptance --env-file infra/compose/.env.ci.example -f infra/compose/compose.prod.yml down -v --remove-orphans
```

本地验收不等于远端 CI、真实 OSS/CDN 音频与 CORS、真实域名/HTTPS 安装、部署、备案、真实 SMTP、备份恢复或生产验收通过。

## 7. 常见问题

### 端口已被占用

PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 3000,5432,8080 -ErrorAction SilentlyContinue
```

POSIX Shell：

```sh
ss -ltnp | grep -E ':3000|:5432|:8080'
```

停止占用端口的进程，或修改 `.env` 中的宿主机端口。容器内部 API 地址仍然是 `http://api:8080`，不要在 Compose 容器内使用 `localhost` 访问 API。

### API 因管理员配置无法启动

检查 `.env` 中同时存在以下两项，并且密码哈希完整、未被 PowerShell 或编辑器截断：

```dotenv
HAOBLOG_ADMIN_USERNAME=admin
HAOBLOG_ADMIN_PASSWORD_HASH=...
```

Compose 使用 `:?` 强制校验这两个变量，缺少变量时会在启动前直接报错。

### Flyway 迁移失败

先查看 API 和 PostgreSQL 日志：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml logs --tail=200 api postgres
```

如果只是可丢弃的本地开发数据库，确认数据不需要保留后再执行：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml down -v
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

### Web 无法连接 API

先确认 API 健康检查通过，再检查 Nuxt API 基地址：

- Compose Web 容器：`http://api:8080`
- 本机直接运行 Web：`http://localhost:8080`

不要把 Compose 内部地址和浏览器直接访问地址混用。

### `mvn verify` 无法运行

确认 Java 版本为 21，并确认 Docker daemon 正常运行。`./mvnw -DskipITs verify` 不启动 Testcontainers；`./mvnw failsafe:integration-test failsafe:verify` 才需要 Docker。不能因为集成测试环境失败就删除或绕过 Failsafe。

## 8. 推荐日常流程

```text
启动 Docker Desktop
  -> docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
  -> corepack pnpm install --frozen-lockfile（依赖变化时执行）
  -> corepack pnpm --filter @haoblog/api-client generate（API 契约变化时执行）
  -> 开发代码
  -> corepack pnpm --dir apps/web typecheck
  -> corepack pnpm --dir apps/web test
  -> Push-Location apps/api; .\mvnw.cmd -DskipITs verify; Pop-Location
  -> corepack pnpm smoke
  -> docker compose --env-file .env -f infra/compose/compose.dev.yml down（结束开发，保留数据）
```

后续阶段涉及数据库迁移时，提交新迁移脚本、API 契约、生成客户端和对应测试；不要直接修改已有迁移文件。
