# HaoBlog 本地启动指南

本文适用于本地开发和阶段三公开阅读验收。默认使用 Docker Compose 提供 PostgreSQL/pgvector、Spring Boot API 和 Nuxt Web；生产 Compose 只用于与 CI 等价的本地验收或真实生产环境，不作为日常开发启动方式。

## 最简启动

仅用于本机快速验证，不要用于生产环境。需要 Docker Desktop 已启动。

Windows PowerShell：

```powershell
Copy-Item infra/compose/.env.ci.example .env.local
docker compose --env-file .env.local -f infra/compose/compose.dev.yml up -d --build
```

POSIX Shell：

```sh
cp infra/compose/.env.ci.example .env.local
docker compose --env-file .env.local -f infra/compose/compose.dev.yml up -d --build
```

然后访问 <http://localhost:3000>。本地测试登录账号为 `admin`，密码为 `password`。

停止服务但保留数据库：

```powershell
docker compose --env-file .env.local -f infra/compose/compose.dev.yml down
```

如果要删除本地数据库数据，在确认数据不再需要后执行 `down -v`。

## 1. 环境要求

| 工具 | 版本/要求 |
| --- | --- |
| Git | 可正常执行 `git` |
| Java | 21（API 编译、测试和本地运行要求 Java 21） |
| Node.js | 24.x |
| pnpm | 11.16.0，仓库已在根 `package.json` 固定 |
| Docker Desktop | 运行中的 Docker daemon，并包含 Compose |

在仓库根目录执行以下命令确认环境：

```powershell
java -version
node --version
corepack pnpm --version
docker version
docker compose version
```

POSIX Shell 使用相同命令；如果 Corepack 尚未启用，可以先执行：

```sh
corepack enable
corepack pnpm --version
```

## 2. 首次准备

所有命令都从仓库根目录 `G:/work/HaoBlog`（或当前检出的仓库目录）执行。

### 2.1 创建本地环境文件

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

POSIX Shell：

```sh
cp .env.example .env
```

编辑 `.env`，至少替换以下值：

```dotenv
POSTGRES_PASSWORD=仅用于本机的随机密码
JDBC_DATABASE_PASSWORD=与 POSTGRES_PASSWORD 相同
HAOBLOG_ADMIN_USERNAME=admin
HAOBLOG_ADMIN_PASSWORD_HASH=BCrypt 哈希
```

`HAOBLOG_ADMIN_PASSWORD_HASH` 必须是 BCrypt 哈希，不能写明文密码。仓库中的 `infra/compose/.env.ci.example` 提供了测试用哈希，对应测试密码为 `password`，只适合临时本地验证；个人开发建议生成自己的哈希并只保存在未提交的 `.env` 中。

不要把 `.env` 提交到 Git，也不要把真实密码、OSS AccessKey 或生产连接信息写入 `.env.example`。

### 2.2 安装 Web 依赖

```powershell
corepack pnpm install --frozen-lockfile
```

```sh
corepack pnpm install --frozen-lockfile
```

该命令必须在仓库根目录执行，以便 pnpm 识别 workspace 和根锁文件。

### 2.3 生成 API 客户端

```powershell
corepack pnpm --filter @haoblog/api-client generate
```

```sh
corepack pnpm --filter @haoblog/api-client generate
```

生成文件位于 `packages/api-client/src/generated.ts`。不要手工修改生成文件；API 契约变化后重新生成并检查 Git diff。

## 3. 推荐方式：Compose 启动完整开发栈

### 3.1 启动

Windows PowerShell：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

POSIX Shell：

```sh
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

首次启动会构建 API 和 Web 镜像，可能需要较长时间。开发 Compose 包含：

- PostgreSQL 17 + pgvector，宿主机默认 `127.0.0.1:5432`。
- Spring Boot API，宿主机默认 `127.0.0.1:8080`。
- Nuxt Web，宿主机默认 `127.0.0.1:3000`。
- Flyway 自动从空数据库执行迁移。
- `HAOBLOG_SEED_ENABLED=true` 时写入开发种子数据。

如果端口冲突，可以在 `.env` 中调整 `POSTGRES_PORT`、`API_PORT` 或 `WEB_PORT`，然后重新执行 Compose 命令。

### 3.2 检查服务状态

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml ps
```

三个服务均应处于 `running`，并且健康检查通过。随后打开：

- Web：<http://localhost:3000>
- API 健康检查：<http://localhost:8080/actuator/health>
- 公共站点接口：<http://localhost:8080/api/v1/public/site>

健康检查只暴露状态，不会返回数据库详细信息。

### 3.3 验证完整开发栈

Windows PowerShell：

```powershell
$env:HAOBLOG_BASE_URL = 'http://localhost:3000'
corepack pnpm smoke
```

POSIX Shell：

```sh
HAOBLOG_BASE_URL=http://localhost:3000 corepack pnpm smoke
```

Smoke test 会检查首页、公共站点接口、文章详情（如果有种子文章），并确认 Actuator 没有通过 Web 公网暴露。

## 4. 本地直接运行 API 和 Web

这种方式适合只调试某一端；PostgreSQL 仍建议由 Compose 提供。

### 4.1 只启动 PostgreSQL

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d postgres
```

```sh
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d postgres
```

API 直接运行时需要在当前终端提供数据库和管理员配置。PowerShell 示例：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:JDBC_DATABASE_URL = 'jdbc:postgresql://localhost:5432/haoblog_dev'
$env:JDBC_DATABASE_USERNAME = 'haoblog_dev'
$env:JDBC_DATABASE_PASSWORD = '替换为 .env 中的数据库密码'
$env:HAOBLOG_ADMIN_USERNAME = 'admin'
$env:HAOBLOG_ADMIN_PASSWORD_HASH = '替换为 BCrypt 哈希'
$env:HAOBLOG_SEED_ENABLED = 'true'
```

POSIX Shell 示例：

```sh
export SPRING_PROFILES_ACTIVE=local
export JDBC_DATABASE_URL=jdbc:postgresql://localhost:5432/haoblog_dev
export JDBC_DATABASE_USERNAME=haoblog_dev
export JDBC_DATABASE_PASSWORD='替换为 .env 中的数据库密码'
export HAOBLOG_ADMIN_USERNAME=admin
export HAOBLOG_ADMIN_PASSWORD_HASH='替换为 BCrypt 哈希'
export HAOBLOG_SEED_ENABLED=true
```

### 4.2 启动 API

Windows PowerShell：

```powershell
Push-Location apps/api
.\mvnw.cmd spring-boot:run
Pop-Location
```

POSIX Shell：

```sh
cd apps/api
./mvnw spring-boot:run
```

API 默认监听 `http://localhost:8080`。此终端保持运行，再打开新的终端启动 Web。

### 4.3 启动 Web 开发服务器

本机直接运行时要把 Nuxt API 地址设为 `localhost`；`http://api:8080` 只适用于 Compose 网络。

Windows PowerShell：

```powershell
$env:NUXT_API_BASE_URL = 'http://localhost:8080'
corepack pnpm --dir apps/web dev
```

POSIX Shell：

```sh
export NUXT_API_BASE_URL=http://localhost:8080
corepack pnpm --dir apps/web dev
```

Web 默认监听 `http://localhost:3000`。Nuxt 服务端通过配置的 API 地址访问后端；在 Compose 网络内使用 `http://api:8080`，本机直接运行时使用 `http://localhost:8080`。

## 5. 常用验证命令

### Web

```powershell
corepack pnpm --dir apps/web typecheck
corepack pnpm --dir apps/web test
corepack pnpm --dir apps/web build
corepack pnpm web:budget
```

### API

Windows PowerShell：

```powershell
Push-Location apps/api
.\mvnw.cmd -DskipITs verify
.\mvnw.cmd failsafe:integration-test failsafe:verify
Pop-Location
```

POSIX Shell：

```sh
cd apps/api
./mvnw -DskipITs verify
./mvnw failsafe:integration-test failsafe:verify
```

第一条命令运行单元、架构和打包检查并显式跳过集成测试；第二条只运行 PostgreSQL/pgvector Testcontainers 集成测试，因此需要 Docker daemon 正常运行。分开执行与 CI 顺序一致，并避免重复运行单元测试。

### OpenAPI 与生成客户端

```powershell
corepack pnpm --filter @haoblog/api-client generate
corepack pnpm --filter @haoblog/api-client check
git diff --exit-code -- packages/api-client/src/generated.ts
```

`generate` 只写入 `packages/api-client/src/generated.ts`；`check` 验证它与 `docs/openapi/public-api.yaml` 一致。不要在 `apps/web` 手写重复 DTO。

### Compose 配置校验

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml config
```

生产配置只做语法校验时，应使用外部生产环境文件，不要使用本地 `.env` 直接启动生产 Compose：

```powershell
docker compose --env-file <production-env-file> -f infra/compose/compose.prod.yml config
```

仓库提供的 CI 示例只能用于本地离线验收：

```powershell
docker compose --env-file infra/compose/.env.ci.example -f infra/compose/compose.dev.yml config --quiet
docker compose --env-file infra/compose/.env.ci.example -f infra/compose/compose.prod.yml config --quiet
corepack pnpm compose:verify
```

### 阶段三生产编排验收

完整命令见 [阶段三准入清单](阶段三准入清单.md)。验收时使用独立项目名 `haoblog-s3-acceptance`，构建 `haoblog-api:ci`、`haoblog-web:ci` 后启动生产 Compose，再依次运行 Smoke、Playwright、客户端预算和 Lighthouse。Playwright 使用测试账号 `admin/password`，必须配合 `infra/compose/.env.ci.example`，不能指向生产数据。

Lighthouse 审计已运行的 Caddy 时需要：

```powershell
$env:LHCI_EXISTING_SERVER = 'true'
$env:LHCI_BASE_URL = 'http://localhost'
corepack pnpm web:lighthouse
```

本地验收不等于真实 OSS、域名 HTTPS、备案或部署通过；这些项目必须在具备真实配置后单独验收。

## 6. 停止和清理

### 停止容器，保留数据库数据

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml down
```

### 停止并删除本地数据库 volume

以下操作会删除本地开发数据库中的数据，执行前确认没有需要保留的文章：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml down -v
```

POSIX Shell 使用相同的 Compose 命令。不要对工作区或未确认的 volume 执行递归删除。

### 查看日志

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml logs --tail=100 api web postgres
```

持续跟踪单个服务：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml logs -f api
```

## 7. 常见问题

### 端口已被占用

PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 3000,5432,8080 -ErrorAction SilentlyContinue
```

POSIX Shell：

```sh
ss -ltnp | grep -E ':3000|:5432|:8080'
```

停止占用端口的进程，或修改 `.env` 中的宿主机端口。容器内部 API 地址仍然是 `http://api:8080`，不要在 Compose 容器内使用 `localhost` 访问 API。

### API 因管理员配置无法启动

检查 `.env` 中同时存在以下两项，并且密码哈希完整、未被 PowerShell 或编辑器截断：

```dotenv
HAOBLOG_ADMIN_USERNAME=admin
HAOBLOG_ADMIN_PASSWORD_HASH=...
```

Compose 使用 `:?` 强制校验这两个变量，缺少变量时会在启动前直接报错。

### Flyway 迁移失败

先查看 API 和 PostgreSQL 日志：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml logs --tail=200 api postgres
```

如果只是可丢弃的本地开发数据库，确认数据不需要保留后再执行：

```powershell
docker compose --env-file .env -f infra/compose/compose.dev.yml down -v
docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
```

### Web 无法连接 API

先确认 API 健康检查通过，再检查 Nuxt API 基地址：

- Compose Web 容器：`http://api:8080`
- 本机直接运行 Web：`http://localhost:8080`

不要把 Compose 内部地址和浏览器直接访问地址混用。

### `mvn verify` 无法运行

确认 Java 版本为 21，并确认 Docker daemon 正常运行。`./mvnw -DskipITs verify` 不启动 Testcontainers；`./mvnw failsafe:integration-test failsafe:verify` 才需要 Docker。不能因为集成测试环境失败就删除或绕过 Failsafe。

## 8. 推荐日常流程

```text
启动 Docker Desktop
  -> docker compose --env-file .env -f infra/compose/compose.dev.yml up -d --build
  -> corepack pnpm install --frozen-lockfile（依赖变化时执行）
  -> corepack pnpm --filter @haoblog/api-client generate（API 契约变化时执行）
  -> 开发代码
  -> corepack pnpm --dir apps/web typecheck
  -> corepack pnpm --dir apps/web test
  -> Push-Location apps/api; .\mvnw.cmd -DskipITs verify; Pop-Location
  -> corepack pnpm smoke
  -> docker compose --env-file .env -f infra/compose/compose.dev.yml down（结束开发，保留数据）
```

后续阶段涉及数据库迁移时，提交新迁移脚本、API 契约、生成客户端和对应测试；不要直接修改已有迁移文件。
